## Почему именно конфиг

В вехе 1 `config.rs` умеет только читать — намеренно: два процесса, пишущих один
`config.json`, гарантированно устроят гонку и потеряют данные.

Это же ограничение блокирует всё остальное. Девять эндпоинтов не могут уехать на
Rust, пока владельцем файла остаётся Python:

| Эндпоинт | Файл, строка |
|---|---|
| `GET /api/config` | `mkdsc/web/server.py:292` |
| `GET /api/config/full` | `:308` |
| `POST /api/config` (частичный патч) | `:318` |
| `PUT /api/config` (полная замена) | `:330` |
| `POST /api/devices/save` | `:428` |
| `DELETE /api/devices/{ip}/{port}` | `:443` |
| `GET /api/presets` | `:514` |
| `POST /api/presets` | `:520` |
| `DELETE /api/presets/{name}` | `:543` |

Веха 2 переносит владение конфигом в Rust целиком и вместе с ним — все девять.
После этого остаётся один крупный кусок (устройства, scrcpy, запись, файлы) и
замена WebSocket на события Tauri.

## Задача 1 — `config.rs` становится владельцем

Портируется `mkdsc/config.py` (281 строка). Нужны: `DEFAULT_CONFIG`,
`_deep_merge`, `_migrate_config`, атомарная запись, резервирование битого файла.

### Атомарная запись

Как в Python: запись во временный файл **в том же каталоге**, затем
`std::fs::rename` (на Windows — `fs::rename` поверх существующего файла падает,
нужен `File::create` + `persist`, либо `fs::remove_file` + `rename`; проще всего
взять крейт `tempfile` с `NamedTempFile::persist`). Плюс процессный `Mutex`
вокруг пары чтение-изменение-запись, иначе `POST /api/presets` и
`POST /api/devices/save` затрут друг друга.

### ⚠ Ловушка: порядок ключей

Python пишет `json.dumps(config, indent=2, ensure_ascii=False)`, и словарь
сохраняет порядок вставки из `DEFAULT_CONFIG`. `serde_json` по умолчанию
использует `BTreeMap` и **отсортирует ключи по алфавиту** — файл перетасуется целиком
при первой же записи, пользовательские правки перемешаются, а каждый diff станет
нечитаемым.

Включить у `serde_json` фичу `preserve_order` (тянет `indexmap`) и работать через
`serde_json::Value`, а не через типизированные структуры с `BTreeMap`. Проверить
тестом: прочитать эталонный `config.example.json`, записать без изменений,
сравнить с исходником побайтово.

Так же проверить `ensure_ascii=False` — кириллица в путях и именах устройств
должна остаться кириллицей, а не превратиться в `\uXXXX`.

### ⚠ Паритет миграции

`_migrate_config` содержит 12 проверок `isinstance` — это результат
исправления бага, когда сохранение `null` в любой секции делало приложение
неработоспособным навсегда. Расхождение в Rust означает либо тот же баг,
либо тихий сброс пользовательского конфига на дефолты.

**Спецификация — `tests/test_config.py` (96 строк).** Портировать каждый случай
оттуда в Rust-тесты один в один. Не «написать свои тесты по мотивам», а
воспроизвести существующие: они уже описывают ожидаемое поведение.

Отдельно сохранить семантику `_deep_merge`: словари сливаются рекурсивно,
списки заменяются целиком, удалить ключ патчем нельзя. Именно поэтому существует
отдельный `PUT /api/config` — он заменяет конфиг полностью. Обе формы должны
работать как раньше.

## Задача 2 — Python перестаёт писать

Пока Rust не стал единственным писателем, ничего не заработает надёжно.

Места, где Python пишет конфиг:

```
mkdsc/config.py:220   load_config()      обратная запись после миграции
mkdsc/config.py:225   load_config()      создание конфига при первом запуске
mkdsc/config.py:266   update_config()
mkdsc/config.py:280   (полная замена)
mkdsc/devices.py:29   save_device()
mkdsc/devices.py:40   remove_device()
mkdsc/web/server.py:539, :550   пресеты
mkdsc/cli/app.py:300  настройки scrcpy из CLI
```

Обратная запись в `load_config()` — самая неочевидная: она срабатывает на
обычном чтении.

**Решение:** переменная окружения `MKDSC_CONFIG_READONLY=1`, которую выставляет
Rust-лаунчер при спавне бэкенда (рядом с уже существующими `MKDSC_HOST`,
`MKDSC_PORT` — см. `src-tauri/src/main.rs`). При ней `save_config()` бросает
понятную ошибку, а `load_config()` пропускает обратную запись.

Так standalone-режим (`python web_panel.py`) продолжает работать как раньше и не
ломается посреди миграции, а в десктопном приложении писатель ровно один.

Чтение конфига Python **сохраняет** — оно нужно для запуска scrcpy, записи и
вычисления путей.

## Задача 3 — девять эндпоинтов

Зеркалим REST один в один, решение зафиксировано в `AGENTS.md`. Формы ответов
брать из `mkdsc/web/server.py` буквально.

`GET /api/config` возвращает поле `languages` из `available_languages(LEXICON_WEB)`.
Сам словарь локалей (`mkdsc/i18n/lexicon_web.py`, 508 строк) в этой вехе **не
переносить** — `GET /api/i18n` остаётся на Python. В Rust достаточно константы
со списком языков плюс тест, сверяющий её с ключами `LEXICON_WEB`, чтобы список
не разъехался.

Роутер в `frontend/src/lib/api.ts` придётся расширить: появляются параметры пути
(`/api/presets/{name}`, `/api/devices/{ip}/{port}`). Заготовка под это в вехе 1
уже сделана — довести до рабочего состояния. Имя пресета и IP приходят
url-encoded, декодировать.

## Порядок работ

1. Ветка `feat/rust-port-m2` от `main`.
2. Задача 1, `config.rs` + портированные тесты → коммит.
3. Задача 2, read-only режим Python + `MKDSC_CONFIG_READONLY` в лаунчере → коммит.
4. Задача 3, эндпоинты порциями: сначала чтение (`GET /api/config`,
   `/api/config/full`, `/api/presets`), потом запись (`POST`/`PUT`/`DELETE`) → коммиты.
5. Роутер → коммит.
6. `CHANGELOG.md` — в тех же коммитах. Перенос эндпоинта пользователю не виден и
   в changelog не идёт; а вот «конфиг больше не может быть перезаписан двумя
   процессами одновременно» — виден.
7. Проверки: `cargo test`, `cargo clippy`, `pytest`,
   `cd frontend && npm run typecheck && npm run lint && npm run build`.
8. Если изменился `static/` — пересобрать и закоммитить, иначе CI упадёт на шаге
   «Verify static/ is up to date».
9. `git log main..HEAD --format='%h %(trailers)'` — пусто.

## Приёмка

Основной сценарий, в собранном десктопном приложении:

1. Открыть Настройки → Конфигурация, изменить пресет, сохранить.
2. `config.json` обновился, значение применилось.
3. **Порядок ключей в файле не изменился** — `git diff` показывает только
   изменённое поле, а не перетасовку целиком.
4. В devtools нет HTTP-запросов ни к одному из девяти путей.

Контрольная проверка (доказывает, что маршруты действительно уехали): временно
вернуть в Python на `POST /api/config` ответ 500. Десктоп не должен заметить,
`python web_panel.py` — должен сломаться.

Проверка единственного писателя: запустить десктоп, сохранить пресет,
одновременно сохранить устройство. Оба изменения должны остаться в файле —
ни одно не потеряться.

Проверка совместимости: взять существующий `config.json` с накопленными
устройствами и пресетами, запустить новую сборку, убедиться, что ничего не
пропало и не сбросилось на дефолты.

**WSL2** — `cargo test`, паритет миграции, атомарность записи, поведение при

открывает ли scrcpy своё окно из упакованного приложения, работает ли диалог

должна проходить дальше. Если дойдут руки — прогнать `release.yml` и

## Чего в этой вехе делать НЕ нужно

- Не переносить `/api/i18n` и словари локалей.
- Не трогать WebSocket и `wsUrl()` — это следующая веха.
- Не переносить scrcpy, запись, файловый менеджер, галерею и сервисные команды.
- Не переносить скачивание инструментов и контрольные суммы — этим по-прежнему
  занимается Python.
- Не редизайнить контракт: зеркалим REST один в один.
- Не удалять Python-эндпоинты, которые переехали. Они остаются рабочими для
  веб-панели до конца миграции; роутер просто перестаёт к ним обращаться.
